# ระบบจ่ายเงินร้านและไรเดอร์ — แบบนำร่อง (ร่างเพื่ออนุมัติ)

**สถานะ: อนุมัติแล้ว 2026-11-08 (DEC-073)** · เขียน 2026-11-08 · LAUNCH_PLAN ขั้น 2 · ต่อจาก DEC-070 Q4
("รายสัปดาห์ โอนมือจากรายงานของระบบ") และ Q5 ("ตารางเรียบๆ ก่อน")

## 1. หลักการ

**ระบบคำนวณ — เจ้าของโอนเอง — ระบบบันทึกว่าโอนแล้ว** ระบบไม่โอนเงินเอง
ไม่เก็บเลขบัญชีเต็ม ไม่เชื่อมธนาคาร

## 2. ใครได้เงินเท่าไร (คำนวณจากข้อมูลที่บันทึกตายตัวไว้ต่อออเดอร์แล้ว)

| ผู้รับ | ได้เงินเมื่อ | จำนวน | มาจาก |
|---|---|---|---|
| **ร้าน** | ออเดอร์ `DELIVERED` | ค่าอาหาร − คอมมิชชั่น 10% | `orders.subtotal_satang` − `order_commission_snapshots` (ตายตัวตั้งแต่สร้างออเดอร์) |
| **ไรเดอร์** | งานส่ง `DELIVERED` | ค่าไรเดอร์ของงานนั้น (80% ของค่าส่ง ขั้นต่ำ ฿12) | `deliveries.rider_earning_satang` (ตายตัวตอนส่งสำเร็จ) |

ตัวอย่าง: ค่าอาหาร ฿180 ค่าส่ง ฿15 → ร้านได้ ฿162 ไรเดอร์ได้ ฿12

**ไม่นับในรอบจ่ายอัตโนมัติ (ทีมงานจัดการเองเป็นกรณีไป):**
- ออเดอร์ยกเลิก / คืนเงิน — ร้านและไรเดอร์ไม่ได้เงิน (ยังไม่ได้ทำอาหาร/ส่ง)
- ส่งไม่สำเร็จ (`DELIVERY_FAILED`) — DEC-053 กำหนดว่าใครรับภาระตามสาเหตุ
  แต่ค่าชดเชยไรเดอร์ (BQ-024) ยังไม่ตัดสิน → แสดงในรายงานเป็นรายการ "ต้องตรวจเอง"
- ไรเดอร์ถูกยกเลิกงานระหว่างทาง (BQ-024) → เหมือนกัน

## 3. รอบจ่าย

- รอบละ 1 สัปดาห์: **จันทร์ 00:00 ถึงอาทิตย์ 23:59 เวลาไทย** นับตามเวลาส่งสำเร็จ
- เจ้าของเปิดรายงานวันจันทร์ โอนเงิน แล้วกดบันทึก
- ออเดอร์ที่จ่ายแล้ว**จ่ายซ้ำไม่ได้** (ระบบบังคับระดับฐานข้อมูล)
- ออเดอร์ที่ยังไม่ได้จ่ายในรอบก่อน (เช่น ลืม) ยกยอดมาแสดงในรอบถัดไปเอง

## 4. หน้าจอ (เว็บ admin เมนู "จ่ายเงิน")

1. เลือกสัปดาห์ → ตาราง **ร้าน**: จำนวนออเดอร์, ค่าอาหาร, คอมมิชชั่น, **ยอดโอน**
   และตาราง **ไรเดอร์**: จำนวนงาน, **ยอดโอน** — รวมยอดค้างจากรอบก่อนด้วย
2. ปุ่ม **ดาวน์โหลด CSV** (ไว้โอนผ่านแอปธนาคาร/เก็บหลักฐาน)
3. แต่ละแถว ปุ่ม **บันทึกว่าโอนแล้ว** → ใส่วันที่โอน + เลขอ้างอิงจากสลิปธนาคาร
   → ระบบบันทึกว่ารายการไหนจ่ายแล้ว ใคร/เมื่อไร
4. ประวัติการจ่ายย้อนหลัง
5. ADMIN เท่านั้นที่บันทึกการโอนได้ OPERATOR ดูได้อย่างเดียว

**หน้ารายได้ของร้าน (เว็บร้าน) และไรเดอร์ (แอปไรเดอร์):** ตารางเรียบๆ แสดงยอดรอบนี้
ยอดที่จ่ายแล้ว และรายการออเดอร์ — อ่านอย่างเดียว ทำเป็นขั้นที่สองหลังหน้า admin

## 5. ข้อมูล (migration ใหม่ — ต้องอนุมัติ)

- `payouts` — การโอนหนึ่งครั้งให้หนึ่งผู้รับ: ผู้รับ (ร้าน/ไรเดอร์), รอบสัปดาห์, ยอดรวม,
  วันที่โอน, เลขอ้างอิงสลิป, ผู้บันทึก — แก้/ลบไม่ได้ (บันทึกผิด → บันทึกการยกเลิกแยก)
- `payout_items` — ออเดอร์/งานส่งที่อยู่ในการโอนนั้น พร้อมยอดของแต่ละรายการ
  **unique ต่อออเดอร์ (ร้าน) และต่องานส่ง (ไรเดอร์)** → จ่ายซ้ำไม่ได้
- ทั้งสองตาราง API เท่านั้น (ไม่มีสิทธิ์จากแอปโดยตรง)

## 6. เรื่องบัญชี (ledger) — ตั้งใจไม่แตะในนำร่อง

ledger ตอนนี้บันทึกรายได้ BANHAO, คืนเงิน และค่าไรเดอร์ แต่**ไม่เคยบันทึกยอดที่ค้างร้าน**
(ช่องว่างที่บันทึกไว้แล้วใน CURRENT_STATUS) นำร่องนี้จึงใช้ข้อมูลตายตัวของออเดอร์เป็นฐาน
และใช้ `payouts` เป็นหลักฐานการจ่าย ส่วนการทำ ledger ให้สมบูรณ์ (ยอดค้างร้าน +
การจ่ายออก) เป็นงานแยกหลังนำร่อง — **ไม่ใช่การปิดบัญชีแบบสมบูรณ์ ใช้สำหรับนำร่องเท่านั้น**

## 7. เลขบัญชีธนาคาร

นำร่อง: **ระบบไม่เก็บเลขบัญชีเต็ม** เจ้าของเก็บเองนอกระบบ (ตาราง `merchant_bank_accounts`
มีอยู่แต่การเข้ารหัสเลขบัญชี DBQ-004 ยังไม่ตัดสิน ไรเดอร์ยังไม่มีตาราง) — ลดความเสี่ยง
ข้อมูลรั่ว ค่อยทำทีหลังพร้อมระบบโอนอัตโนมัติ
