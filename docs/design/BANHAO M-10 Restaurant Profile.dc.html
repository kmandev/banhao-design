BANHAO | บ้านเฮา · design artifact for docs/design/ · design only, no implementation
Screen M-10 โปรไฟล์ร้าน — the merchant-facing editor for restaurants' descriptive fields. Read against 20260811000002_merchant_domain.sql, 20260811000011_rls_policies.sql, the existing cover-upload API, and the merchant web app at ac2c88c5. Only the cover photo has a working write path today. Every other field on this page is designed as an editable form control that currently has nowhere to send its data — each is labelled accordingly. In-product copy is Thai, all annotation is English.
Blocking finding. restaurants has zero INSERT/UPDATE grant to authenticated — the RLS migration grants that role SELECT only. The cover-photo flow works because RestaurantCoverService writes through the service-role connection after its own guard chain, never through client RLS. Every field this screen edits needs the same shape of new work: a guarded controller route, a service-role write, and — for name/description/phone/address_line/cuisine — a validation schema in packages/validation, none of which exist yet.

00 — SCOPE
The descriptive half of the storefront, not its lifecycle
A restaurant's identity (name, description, cuisine, image_url, phone, address_line) is one page. Who runs the restaurant, whether it's approved, whether it's open right now, and where its delivery zone sits are each a different, deliberately excluded, domain.

TEMPORARY CLOSURE — ACCOMMODATED, NOT DESIGNED
temporarily_closed_until and temporary_close_reason exist on the table and this screen's status pill (§03 header) is left as the one place a future closure indicator could attach without reflowing the page. What would be needed: a way to display an active closure end-time and reason next to the status pill, and a control to set/clear both fields. What is deliberately not decided here: exact duration rules, whether reopening is automatic or manual, which restaurant_member role may trigger it, how it interacts with status, and any customer-facing copy. This holds the same boundary M-12 already recorded against BQ-007 (OPEN) — hours, temporary closure and order acceptance stay three separate decisions.
