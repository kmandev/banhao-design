DRIVER + DELIVERY — COMPLETE FLOW
BANHAO | บ้านเฮา · design package for docs/design/ · design only, no implementation
One package for the whole rider journey: sign in, availability, offer, the four delivery steps, proof of delivery, completion, and every architecture-supported failure between them. Read against docs/RIDER_LIFECYCLE.md, docs/DRIVER_APP_DESIGN_QUESTIONS.md, docs/CURRENT_STATUS.md, docs/TODO.md and the shipped apps/driver/src at branch feature/g7-driver-availability. In-product copy is Thai and is quoted from the shipped screens wherever it already exists; all annotation is English.
Locked architecture governs every screen here. Dispatch is broadcast, first accept wins (DEC-020) with a 60 s accept window and a 60 s re-broadcast round (DEC-037). A rider holds one active delivery (BQ-021). The four rider transitions are the only ones drawn, and a completion is refused without a proof photo (DEC-038) — the rule lives in the API, never in the client. No money appears on any rider surface: BQ-029 is OPEN and rider_earning_satang is NULL by instruction.
