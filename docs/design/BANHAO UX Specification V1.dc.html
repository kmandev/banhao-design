Prolonged rider search is not an order state
After 5 minutes the customer is told — ยังหาไรเดอร์ไม่ได้ · เรากำลังเร่งหาให้ — with the 3-minute extension offer, and an operator alert opens in A-13. The order stays in PREPARING or READY_FOR_PICKUP. Only an operator decision ends it, and cancelling is one option among several (DEC-022).
Cancellation availability mirrors ORDER_LIFECYCLE.md §5 exactly and derives nothing: free before cooking, merchant-confirmed during, support-only from PICKED_UP. Every dialog states the refund consequence before it asks for confirmation.

UX-FINDING-01 · needs a Product Owner answer
A 16px primary button label on #E4572E does not meet AA
Two cheap remedies, and this specification chooses neither because the primary colour is a brand decision: raise primary labels to 17–18px/700 — defensible on a 56px button and better for Thai anyway — or use #C2431F as the fill for text-bearing buttons and keep #E4572E for fills and accents. Recorded as UX-Q-001. It touches every button in the product, so it should be answered before implementation, not after.
Thai-first typography rules — binding
Every component is laid out against the longest real Thai string it will carry, never an English placeholder — พร้อมให้ไรเดอร์รับ and บัญชีถูกระงับการใช้งาน are the stress tests for chips and strips. Thai does not wrap on spaces, so every single-line element declares its overflow behaviour: chips and buttons grow, table cells truncate with a title, status text never truncates. Line height stays 1.55–1.75 everywhere. Numerals are Arabic. No Latin placeholder text anywhere, including skeletons. Android must be verified for per-weight Thai font families before launch — the single most likely rendering failure.
