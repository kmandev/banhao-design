### The hard problem: HTTP/3 in the Simulator

Every request to Supabase after the first failed with `Network request failed`,
and it survived an app restart and a Simulator reboot. Rather than guess, the
Simulator's own log was read:

```
[... quic-connection, url: https://<ref>.supabase.co/auth/v1/otp, tls ...] cancelled
Task <...> finished with error [-1005] "The network connection was lost."
```

The first response advertises `alt-svc: h3`; CFNetwork caches it and switches to
QUIC, which the Simulator's stack cannot sustain against this host. Three pieces
of evidence pinned it down: `curl` **inside the same Simulator runtime** reached
the host fine, the host itself reached Supabase fine, and deleting Expo Go's
`HTTPStorages` database bought exactly one more successful request before the
cache was poisoned again. Expo Go has no switch to disable HTTP/3.

`scripts/sim-supabase-proxy.mjs` resolves it by serving the Simulator plain HTTP
(which never negotiates QUIC) and forwarding every request verbatim to the real
project over HTTPS. **It is a transport shim, not a mock** — sessions are issued
by real GoTrue and RLS is enforced by the real database.

One bug in the proxy was worth the lesson: forwarding the upstream
`content-encoding` header after `fetch()` had already decompressed the body made
the client try to gunzip plaintext and drop the connection — which looked
identical to the original symptom. Stripping the header fixed it.

### What was fixed

**DEF-01 (MAJOR) — `PayExpired` (12e) unreachable.** `PromptPayQrScreen` now
`replace()`s to `PayExpired` when the TTL hits zero. `replace` rather than
`navigate` so Back cannot return to a QR that no longer works.

There was a temptation here worth naming: adding a `ttlSeconds` route param
would have made QA take five seconds instead of ten minutes. It was rejected —
a shortcut added *because* of testing would have meant the screenshot proved a
code path QA had shaped rather than the one users get. 12e was reached by
letting the real 600-second countdown run out, and the unit test drives the same
transition with fake timers.

**DEF-02 — resend was a no-op.** `ขอรหัสใหม่` now calls `requestOtp`, and the
countdown restarts **only on success**. Resetting it on failure would tell a
user a code was coming when none had been sent.

**DEF-03** — explicit `headerBackTitle: 'กลับ'`. **DEF-04** — the selected check
is drawn from two rotated borders rather than U+2713, which the font lacks.
**DEF-05** — `formatThaiPhone` presents `081 234 5678`; the stored E.164
identity is untouched, and a client cannot write `profiles.phone` anyway.

**The status taxonomy changed, so `DOCUMENTED` was renamed to `ACCEPTED`.** The
lock asked for four statuses — `ACCEPTED` / `PROPOSED` / `OPEN` /
`LEGAL_REVIEW_REQUIRED`. EVENT-013 had used `DOCUMENTED` for "traceable to an
accepted source", which is the same idea, so the token was renamed across all

visible because each rule cites its `DEC`/`CON`/`REQ`.

**`ACCEPTED — MODEL · OPEN — NUMBERS` was used as a first-class status.** DEC-023,
DEC-024 and DEC-025 fix the direction of the money and explicitly refuse to fix
the amount. Flattening that to either `ACCEPTED` or `OPEN` would have lost the
distinction the Product Owner drew.

**Two pieces of accepted product truth were superseded — by the Product Owner,
not by an agent — and both are recorded as supersessions, not edits.** DEC-019
replaces the 2026-08-09 Order state machine (so FACT-005 gained a provenance
note and stays VERIFIED as a statement about that artifact), and DEC-016
replaces the Phase 1 payment scope. **DEC-004 and REQ-001 were deliberately not
deleted** — they are marked dormant, because COD is disabled, not abolished.

**Exception state names were left `PROPOSED`.** §6 of the lock approved the
*core* lifecycle; it did not name `PAYMENT_FAILED`, `MERCHANT_REJECTED`,
`DELIVERY_FAILED` or `CANCELLED`. Promoting them would have been an agent
